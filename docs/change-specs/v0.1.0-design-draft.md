# Math Engine v0.1.0 — design draft

Status: proposed technical design, not an approved implementation specification. Repository separation is owner-confirmed on 2026-10-08.

## Proposed first increment
1. Inspect and pin the existing shared-math implementation and catalog before migrating any behavior.
2. Read the current custom standards map; separate source outcome IDs from canonical generator skill IDs.
3. Define generation input: contract version, curriculum/map version, selected skill ID, explicit parameters and seed.
4. Define output: stable item ID, engine/generator version, source outcome IDs, structured prompt/math/visual data, answer contract and solution data.
5. Return unsupported skills explicitly; never substitute another skill silently.
6. Select a small verified skill set for the first Studio integration, then expand coverage against the custom map.

## Contract decisions still open
Exact schema, math representation, random-number algorithm, numeric precision and bundling require source inspection. Same engine version, catalog, parameters and seed must reproduce the same output. Renderer-specific HTML or Word formatting should be handled at the consumer boundary.

## Verification plan
Exercise ordinary and boundary parameters for each implemented generator; independently check solutions and equivalent answers. Check deterministic replay and explicit failures. Include an end-to-end Studio worksheet and key comparison. Game migration and host parity require separate scoped verification before changing those repositories.

## Source readiness
ExamView archive extraction recovered Intermediate 4 and Course 1 original banks and readable fragments. Equations, diagrams and correct-answer associations are not fully decoded. These are reference sources, not ready-to-import engine data. The custom map and existing code remain required inputs.

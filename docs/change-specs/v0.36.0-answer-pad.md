# Math Engine 0.36.0 — the universal answer pad (handbook U-18)

**Status:** Approved by William McAda, 2026-10-15 (Asia/Shanghai): two-tab layout, fractions typed with a slash, the Math Engine as owner, "proceed". Implementation checkpoint until the checks below pass on the exact committed candidate.
**Date:** 2026-10-15
**Baseline:** MATH-ENGINE `main` `9b2abef` (Engine 0.35.0-rc.1).
**Handbook:** mcada-project-handbook v0.1.12, `9d9c80f` — U-18 (approved), U-14 (amended the same day: the Engine owns the answer pad), U-04, U-10, U-17.
**Consumers:** MathQuest and Math Arcade migrate to the pad in their own change specs, pinning this bundle.

## Problem

A student in Math Arcade met a question that needed a remainder "R" and had no way to enter it. No single place owned the answer pad:

- The Engine built each question's key list from its **correct answer** (`bankEntryMode` in `src/practice.js`, `keypadKeys` in the K–7 baseline).
- Each host drew its own pad from that list: three renderers in Math Arcade, two in MathQuest (one of them fixed, with no `/` or `R`).
- Hosts reject characters that are not on the list, so a physical keyboard cannot fill a gap.

Building keys from the answer also **gives answers away**. In the 8/7 division family ("using R when the remainder is nonzero"), the R key appears only when the remainder is nonzero. Expression keys likewise show only when the answer is an expression.

`tests/practice.cjs` excused K–7 skills from its "keys cover the answer" check, so these gaps were not caught.

## Design

### One pad, one key set (U-18)

A new module, `src/answer-pad.js`, owns the pad. Every question offers the same two tabs, and **123** opens first:

| 123 | | | |
| --- | --- | --- | --- |
| 7 | 8 | 9 | ⌫ |
| 4 | 5 | 6 | Clear |
| 1 | 2 | 3 | / |
| 0 | . | − | R |
| : | ; | , | Space |

| Algebra | | | |
| --- | --- | --- | --- |
| x | y | ^ | ⌫ |
| + | − | × | ÷ |
| ( | ) | √ | Clear |
| = | < | > | % |
| ≤ | ≥ | { | } |
| $ | AM | PM | Space |

The key list comes from a survey of every character in Engine answers (all game-eligible items, 30 seeds each, at `9b2abef`). That survey found `; : . / - $ + , ( ) < > × % = R { } ^ ≤ ≥`, `x`, AM/PM and `sqrt` (Algebra radicals).

The module exports:

- **Data:** `tabs`, `keys`, `textFor(key)` (what each key types; ⌫ and Clear are actions) and `allowedCharacters`.
- **Browser helper:** `mountAnswerPad(container, options)` draws the pad, switches tabs, and returns `{ reset, destroy }`. Options are `input` (a text field) or `onChange(text)`, plus `onSubmit`.
- **Behavior:**
  - Each new question opens on **123** (`reset()`).
  - Physical-keyboard typing of any pad character works.
  - Enter submits.
  - Keys take a tap, not a hold. Long-press selection and callouts are suppressed (U-10).
- **Styling:** a stylesheet is injected once. Size and colour are CSS custom properties (`--answer-pad-*`), so a host can fit the pad to its screen without changing keys or order.

The module has no dependencies. Its data part also runs in Node, so Workers and tests can use it.

### Items

- Every item with `inputMode: 'keypad'` gets `keys` equal to the universal key list, whatever its answer.
- `keypadKeys(item)` returns the universal list.
- Items with `inputMode: 'choice'` keep answer buttons.
- Items whose answers are words, letters (A–E), Roman numerals or units keep `inputMode: 'keyboard'` (text box), as U-18's boundary allows.
- **Radical items** that used the keyboard only because their answer text uses `sqrt(...)` and `*` move to the pad, when their answer can be typed with pad keys (`√`, `×`).

### Checking

`evaluate` and `checkAnswer` normalise pad-typed text before handing it to the unchanged layer checkers:

| Typed | Becomes |
| --- | --- |
| `−` | `-` |
| `÷` | `/` |
| `√N`, `√(...)` | `sqrt(N)`, `sqrt(...)` |
| A coefficient before √ (`1/6√37`) | `1/6*sqrt(37)` |

`×` and `*` stay as each checker already accepts them.

The "use only the answer keys shown" rejection now tests against the universal character set (plus `*` for keyboards). Anything the pad can type is never rejected as invalid characters; it is judged as right or wrong.

### Unchanged

- Question text, answers, solutions and IDs.
- Seeds: the same seed and index give the same question.
- The K–7 baseline: still embedded verbatim, sha256 test unchanged.
- The layer checkers' acceptance rules beyond the normalisation above.

`inputMode` stays as-is except for radicals.

## Verification required

- `node tests/practice.cjs` — all prior checks, with these changes:
  - **`keypad-keys-cover-answer`** now applies to **every** layer, including K–7 skills. For every keypad item and seed, the answer, written with pad keys, must be typeable using only the pad.
  - **`answer-pad-uniform`:** every keypad item carries the identical universal key list.
  - **`pad-typed-answers-accepted`:** for every keypad item, the pad-typed form of its answer evaluates correct. That means `−` for minus, `√` for `sqrt`, a coefficient written directly before √, and `R` with or without spaces.
  - **`radicals-on-pad`:** radical items are keypad items and accept `√` entry.
  - **`no-answer-leak`:** in the 8/7 division family, zero- and nonzero-remainder items show identical keys.
- `npm test` and `npm run test:phase2`.
- Browser check of `mountAnswerPad` in a test page:
  - Both tabs render with the listed keys in order.
  - 123 opens first and returns after `reset()`.
  - Keyboard entry and Enter work.
  - At iPad width (1024 × 768 and 768 × 1024) with touch emulation, keys are at least 44 px.
- Physical iPad: Not run in the Engine. Belongs to each host's verification under U-18 and U-10.

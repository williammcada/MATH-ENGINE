# Math Engine 0.66.0 — Intermediate 4 requests R1, R2 and R3

**Status:** Approved by William McAda, 2026-10-17 (Asia/Shanghai): "Approve all; proceed" for the three requests in `docs/change-specs/coverage-i4-pending-requests-v0.1.md`. Implementation checkpoint (0.66.0-rc.1) until the checks below pass on the release candidate.
**Baseline:** MATH-ENGINE `main` `17c4e3a` (Engine 0.65.0, verified release).
**Handbook:** mcada-project-handbook v0.1.16, `7b11826`: U-01 (version), U-04 (mathematics agrees), U-06 (retain behaviour), U-07 (report limits), U-14 (Engine owns generation).

## R1. `scripts/read-examview.py`: keep the row breaks of stacked layouts

In `runs()`, byte 0x0D inside a text run (and in the text after a variable reference) is now a row break printed as ` / `, instead of ending the run. The column 8, 4, 2, + 5 now prints as `8 / 4 / 2 / ⟨T1,131077⟩ + 5` (key 19), where it printed `8 + 5` before.

## R2. `scripts/read-examview.py`: report ExamView native drawing objects

New `drawings()`: each native drawing record in a question's rich data is printed as one `drawing:` line, `[display condition] name or label (coordinate and size slots, as stored)`, for example `drawing: [pick=1] block(3,3,3) (-3, 7, 10, 10)` or `drawing: rhombus (-2, 0, 1, 1)`. Font names, the question and choice text, and variable fields (already under `fields:`) are left out, and stray characters from bitmap data are filtered. Unnamed shapes (circles, lines) print as `shape`. The listing is a reading aid for porting sessions; it is not a renderer, and a few records may still show a stray sign as a label.

Also: the reader now replaces characters the terminal cannot print (some variable names decode to lone surrogates), so reading the whole Course 1 bank no longer stops with `UnicodeEncodeError`. That failure was already present on `main`.

The reader still never writes source text or pictures into the repository.

## R3. Intermediate 4 ports replace the 27 earlier adaptations

Every record in the R3 table now has its own port task with `replacesEarlierAdaptation`, so `course-banks.js` drops the earlier structured entry and every consumer serves the port. No record is consolidated (the table's optional consolidations were not taken, so each record keeps its own source ranges). `PENDING_I4` is empty.

New variants in `src/port-intermediate-4.js`:

| Variant | Records | Source example |
| --- | --- | --- |
| `i4-sub` `tens` | TX4_S02_00125 | 860 − 240 (no dollar sign; `tens-money` keeps it) |
| `i4-sub-zero` `whole-dollars` | TX4_S05_00039, 00074 | $7.65 − $2; $6.78 − $4 |
| `i4-sub-zero` `whole-minus-diff` | TX4_S05_00143 | $27 − ($24.17 − 58¢) |
| `i4-paren` `minus-diff` | TX4_S05_00079 | 9 − (6 − 3); 0 allowed as a choice |
| `i4-missing-factor` `tens-product` | TX4_S05_00099, 00101 | 4a = 240; 7m = 560 |
| `i4-missing-factor` `two-digit` | TX4_S07_00085, 00086 | 4r = 52; 6s = 96 |
| `i4-missing-factor` `two-digit-left` | TX4_S05_00100 | 287 = 7k (product written first, answer 21–49) |
| `i4-dec-add` `minus-sum` | TX4_S05_00088, 00139, TX4_S10_00080 | 5.46 − (1.2 + 3.12) |
| `i4-dates` `between` | TX4_S06_00054 | the month between March and May |

TX4_S05_00100 was listed with 00099, but its source (287 = 7k, answer 41) is a two-digit answer with the product first, not a product in tens, so it got its own variant.

The other records use recipes written in Batches I4-1 to I4-5 (`i4-add-row`, `i4-missing-row`, `i4-add-3digit`, `i4-sub`, `i4-expanded-form`, `i4-angle-name`, `i4-clock2`). One fix there: `i4-expanded-form` `products` threw "too few distractors" for numbers with a zero tens digit (such as the source's 409), because two of its three distractors coincided. It now tops up from two fallback distractors. The fallbacks are used only when needed, so numbers that worked before are unchanged.
